설명

적금 시스템 메인 목표는 돈을 모으는 것으로 상품은 단위기간 별로 1일, 1주, 2주, 3주, 한달로 상품이 존재한다. 일반적인 은행 적금 상품과 마찬가지로 상품에 가입하며 단위기간에 맞춰 정기결제를 한다. 결제 과정에서 2차보안이 들어가 정보유출을 막으며, 매일 자정마다 랭킹을 업데이트 한다. 상품 가입시 중도입금은 제한하며, 자동입금 할 계좌를 기입해야한다. 중도해지 할 경우 일정 수수료를 지불하고 환급받을 수 있으며 만기시 골든볼 신청권 or 이자를 지급한다. 골든볼의 경우 당첨시 중도 해지자들의 수수료 금액을 받을 수 있는 시스템이다. ex) 해지 수수료는 총 금액의 10%로 중도 해지시 10%를 제하고 지급이 되며, 수수료는 모아 골든볼 당첨자에게 일부 금액이 입금된다. ex) 중도 해지 기준 계좌에 천만원이 적금계좌에 존재 -> 900만원이 계좌에 환급 ( 100만원 수수료 ) 골든볼 당첨 시 일부(50% ?) 지급 단 중도 해지자가 없을 경우 골든볼 신청자들은 자동으로 이자 지급으로 변경된다. 최소입금금액과 최대입금금액이 존재한다. 이자 : 일일단위의 경우 시간별로 이자 0.001% , 주단위의 경우 일 별로 이자 0.01% 스케줄링을 통해 시간단위 또는 일단위 또는 주단위의 정기 결제
2.커뮤니티 일반적인 커뮤니티 사이트와 유사하게 기본적인 구조는 문의게시판, 공지게시판 등이 존재하며 금일 랭킹을 확인 할 수 있다.

1.적금시스템 만기기간 별로 끊어서 상품 만들기 추가/수정을 통해서 만기기간별로 끊어서 모집 중도 가입 불가 , 신청기간 따로 모집 상품은 1개월, 3개월, 6개월, 1년 한달짜리는 매일 입금만 가능 나머지는 선택이 가능 (일, 주, 달) 골든볼 + 이자(0.1%) or 이자(이율 압도적으로 높게 하기) 10%받기 선택 모든 중도포기자 수수료 20% 제하고 환급 신분증 검사 + 계좌연동 + 자동이체 이자계산

# 💰 경쟁형 적금 웹 서비스

실제 금융 서비스 흐름을 반영한 **경쟁형 적금 + 커뮤니티 웹 서비스**  
(팀 프로젝트)

---

## 📌 프로젝트 개요

본 프로젝트는 사용자의 저축 동기를 강화하기 위해 **랭킹 시스템과 보상 구조를 결합한 적금 서비스**입니다.  
정기 적금 상품에 가입한 사용자들은 매일/매주 정기 납입을 통해 순위를 경쟁하며,  
만기 시 **이자 또는 골든볼(보너스 보상)** 중 하나를 선택할 수 있습니다.

금융 서비스의 핵심 요소인 **정기 결제, 보안, 만기 처리, 데이터 무결성**을 실제 서비스 수준으로 구현하는 것을 목표로 했습니다.

---

## 🎯 프로젝트 목표

- 실제 은행 적금 서비스의 구조와 사용자 흐름을 분석
- 정기 결제, 만기 처리, 중도 해지 등 금융 로직 구현
- 랭킹 및 보상 시스템을 통해 사용자 참여 유도
- Spring Boot 기반 백엔드 중심의 웹 서비스 설계 및 구현 역량 강화

---

## 🔍 벤치마킹

| 서비스 유형 | 벤치마킹 요소 | 반영 내용 |
|------------|--------------|----------|
| 은행 적금 서비스 | 정기 납입, 만기 이자 지급 | 자동이체 기반 적금 로직 |
| 경쟁형 챌린지 서비스 | 랭킹 시스템 | 매일 자정 랭킹 갱신 |
| 금융 이벤트 서비스 | 보상 구조 | 골든볼(보너스) 시스템 |

**분석 결과**  
기존 적금 서비스의 안정성과 경쟁형 서비스의 참여 요소를 결합하여  
단순 저축을 넘어 **게임적 요소가 있는 금융 서비스**로 설계했습니다.

---

## 🧩 핵심 기능

### ✔ 적금 시스템
- 기간별 적금 상품 (1개월 / 3개월 / 6개월 / 1년)
- 정기 자동이체 (일 / 주 / 월 단위)
- 중도 해지 시 수수료 차감 환급
- 만기 시 **이자 지급 또는 골든볼 선택**
- 매일 00시 기준 랭킹 자동 업데이트

### ✔ 결제 시스템
- Toss API 연동 결제
- 카드 결제 / 계좌 이체
- 자동 결제 설정
- 2차 보안 적용

### ✔ 커뮤니티
- 공지 게시판 / Q&A
- 랭킹 및 당첨자 공지
- 사용자 간 정보 공유

### ✔ 관리자 기능
- 회원 관리
- 적금 상품 등록 / 수정 / 삭제
- 상품별 매출 및 당첨자 관리
- 권한 분리 (ROLE_USER / ROLE_ADMIN)
